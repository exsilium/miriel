# Miriel

RAG chat layer over digitized Elden Ring strategy guides, with page citations.

- Source books: OCR PDF + one image per page, under `data/` (gitignored; `DATA_DIR`, default `./data`, `/data` in Docker). File names, offset and page count per book live in config/books.json (`vol1`, `vol2`); nothing in code may assume a book id, count, offset or file-name pattern.
- Per-page extraction prompt: prompts/page-extraction-prompt.md — treat it as the spec for the model call, do not rewrite it without asking
- Extraction output: out/<book>/p{PAGE:04d}.json, one file per page, schema defined in the prompt. Python runner: `uv run python scripts/extract.py --book <id> <pages>` (`--book` required, ids from the config; `--fixture` uses test-pages/<book>/ built by `scripts/build_fixture.py --book <id> --pages ...`). Offset check for a new book: `scripts/check_offset.py --book <id> --images all [--record]` (folio vs PDF text layer, and every image file vs the photo embedded in its PDF page; stray photos in an image folder shift all later files). The runner skips pages with valid output (`--force` to redo), takes `--pages-from <file>`, shares one rate-limit pause across `--workers`, logs to out/<book>/_runlog.jsonl and prints a cost summary. QA: `scripts/qa_report.py --book <id>` writes out/<book>/_qa.md and _retakes.txt; `scripts/compare_extractions.py <dirA> <dirB>` diffs two runs (model or prompt changes on the fixture). `scripts/extract_split.py --book <id> --page <n> [--parts ...]` transcribes a page the API output filter blocks as rectangular parts and marks blocked parts as gaps.
- Python 3.12, uv for deps, Anthropic SDK. Never commit the PDF, images, or out/.
- Check the source PDF page index vs printed page number offset before anything else.
## Node stack (Phase 1+)

- npm workspaces: packages/shared (zod schema, normalizeName, embedding provider), packages/indexer (CLI). Build with `npm run build` (tsc -b), tests with `npm test` (node:test).
- Book config incl. printed-page to PDF offset: config/books.json (vol1 and vol2 offset = 1, both verified, see `offsetVerified`). Migrations: db/migrations/*.sql, applied by `indexer migrate`.
- Dev database: `docker compose up -d db`, then `node packages/indexer/dist/cli.js migrate|ingest|reset|dump`. `ingest --all` indexes every configured book from out/<id>/ and registers books that have no output yet (so they are browsable). Ingest is incremental: pages whose file sha256 matches `pages.source_hash` (migration 0003) are reported as unchanged and skipped; `--force` redoes them.
- Retrieval harness: `npm run retrieve -- "<query>"` (packages/api, see docs/retrieval.md; full Vol 1 results and the anchor rules (containers, index exclusion, region cap, route span) are documented there). Answer harness: `npm run answer -- [--inline] "<question>"`; system prompt in packages/api/prompts/answer.md (+ answer-citations.md / answer-inline.md per mode).
- HTTP API: `npm run api` (Fastify on PORT 8080; routes in packages/api/src/routes, SSE chat at POST /api/chat). Page thumbnails: GET /api/books/:id/pages/:n/thumb, 240 px JPEG made with sharp on first request and cached under THUMB_CACHE_DIR (default <tmpdir>/miriel-thumbs; the `thumbs` volume at /cache/thumbs in Compose). Answer defaults: ANSWER_MAX_TOKENS 16000 (adaptive thinking counts against it). Dev with hot reload: `npm run dev:api` with CORS_ORIGIN set to the Vite origin.
- Web UI: packages/web (Vite + React + react-pdf). Book selector in the top bar; search scope toggle in the composer (default: all books, i.e. no `bookIds` in POST /api/chat). Deep link `?book=<id>&page=<printed>`. `npm run dev:web` (port 5173, proxies /api to 8080), `npm run build:web` (typecheck + bundle to packages/web/dist). Fuzzy quote highlighting in src/viewer/highlight.ts.
- Docker: `npm run up` (compose up --build, app at http://localhost:3000), `npm run index` (one-shot `ingest --all`, profile "index"), `npm run down` (stops the stack, keeps the data), `npm run reset` (down -v: drops the database, thumbnail and upload volumes; re-index afterwards), `npm run dev` (api + web hot reload against the compose db). Compose mounts `./data` at /data (api) and `./out` at /app/out (indexer). Dockerfile targets: runtime (node) and web (nginx); docker/nginx.conf proxies /api with SSE buffering off.
- Page retakes (docs/build-spec-retakes.md): `npm run retake -- --book <id> --page <printed> --image <file>` (or `--dir <folder>`, `--rollback --page <p>`, `--history`, `--resume <id>`, `--dry-run`). Runs only in the Docker `retake` image (ocrmypdf 16.13 / tesseract 5.5 / pikepdf / qpdf + indexer; uv group `retake`); photos come from RETAKE_INBOX (default ./retakes). Versions: DATA_DIR/_versions/ (PDFs, last 3; saved single pages; journals), <imageDir>/_versions/ (+ log.jsonl), out/<book>/_history/. RETAKE_DATA / RETAKE_OUT / RETAKE_DATABASE_URL point it at a sandbox copy. The book PDFs were never valid PDF/A-2b (XMP `pdf:Author` from exiftool); splices keep info + XMP byte-identical.
- Retake jobs (Phase B): migration 0004 (`retake_jobs`, `retake_events`); api routes in packages/api/src/routes/retakes.ts, only with RETAKE_ENABLED=true (RETAKE_TOKEN guards POSTs; photo = raw image/jpeg|png body, stored in the `uploads` volume). packages/worker (Compose `retake-worker`, retake image) validates uploads and runs confirmed jobs by driving `retake.py --json` (`--validate-only`, `--items`, `--txn-id`, `--resume`); one job per book at a time (advisory lock + retake.py lock file), orphans of a killed worker resume from the journal, the daily budget is summed from the journals.
- Cache-safe serving (retakes Phase C): `pdfRevision` (sha256 prefix of the PDF, cached by size+mtime so a swap is seen on the next request) in GET /api/books; `imageVersion` from `pages.image_sha256` (migration 0005, written by every `ingest` incl. unchanged pages; the indexer mounts ./data read-only for it) in page detail, chat anchors (`imageVersions`) and citations, and GET /api/books/:id/image-versions. URLs with `?v=<current>` are immutable, others `no-cache`; a PDF request with an old `?v` is a 409 (no mixed byte ranges). Thumbnails are cached as p<n>.<version>.jpg. The web client polls /api/books (60 s + tab focus) and reloads the PDF at the same page when the revision changes (src/versions.ts holds the photo versions).
- Retake UI (retakes Phase D): packages/web/src/retakes/ (queue at /retakes, page view /retakes/<book>/<page>, batch /retakes/batch; tiny router in src/route.ts, no dependency). Shown only when GET /api/retakes/config answers (RETAKE_ENABLED); a token field appears when RETAKE_TOKEN is set (kept in localStorage). "Mark accepted" is a retake_jobs row of kind 'accept' (migration 0006). Page identification in retake.py: file name, else folio + photo similarity, else photo similarity alone (perceptual hash distance <= 14 of 64, clear winner); a photo that looks like another page is a hard stop.
- Retake runbook: docs/retakes.md. Every retake/rollback ends with a `qa` stage (qa_report.py) so _qa.md/_retakes.txt match the queue. Full rebuild: `npm run rebuild-pdf -- --book <id> [--dry-run|--yes]` (scripts/rebuild_pdf.py: img2pdf + ocrmypdf over the image folder, outline from data/<pdf stem>.toc.txt or the current PDF, metadata copied with XMP in sync, verified, swapped in as a version, logged as `pdf_rebuilt`); the queue suggests it past 20 % of a book's pages replaced since the last build.
- Fresh install and moving the stack to another machine (copy data/, out/, .env + a pg_dump restored into the empty db; no re-extraction or re-embedding): README. `npm run py -- scripts/<x>.py …` runs any Python script in the retake image; ./config is mounted into indexer, retake (rw, for check_offset --record) and retake-worker.
- Adding a book (Vol 3): docs/adding-a-book.md, the runbook; no code changes. Specs: docs/build-spec.md (v1), docs/build-spec-v2.md (full books, multi-book), docs/build-spec-retakes.md (next: replace a page photo from the UI).
- Never commit node_modules, dist, .env. Chunk dumps contain book text; keep them out of the repo.
